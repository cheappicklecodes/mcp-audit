0.5.0: score detection apart from grading

The benchmark demanded an exact set match per case. A scanner that found the
vulnerability and added an unrelated finding scored that case as a false
negative, and severity was part of the match, so found-it and graded-it-right
were the same bit.

Now three measurements:

- exact-case conformance, which is what a regression suite should gate
- finding-level precision and recall, matching one-to-one on marker spans
- severity agreement, reported as calibration rather than detection

Sinks are anchored with marker comments so a rewrap does not invalidate a
case. expected.json is schemaVersion 2; the old shape is rejected instead of
silently scoring zero, and a malformed corpus exits 2 so it cannot pass for a
clean run. The report states its own provenance: these are maintainer-authored
fixtures, with no independent or held-out cases.

Findings on every anchored rule now carry real offsets, capability-mismatch
anchors on the capability block rather than the whole file, and the argument
rule balances argv arrays on brackets instead of parentheses, which had been
letting its span run past the call.

36/36 exact, 24/24 findings, 100% severity agreement.
